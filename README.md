# Spectra3D Script (SPScript)

A programming language for game engines: Python-like syntax with braces
instead of indentation, a real compiler and a fast virtual machine.

```sps
// Hello World
print("Hello World!");
```

The file extension of the scripts is **`.sps`**, the data format of the
engine is **`.spl`**.

---

## Quick start

```bash
build.bat                       # build (gcc from MSYS2 / MinGW)
bin\spsc.exe examples\hello.sps # compile and run
```

The compiler writes `out/hello.spc` — the bytecode — which can be run
separately:

```bash
bin\spsvm.exe out\hello.spc
```

### Commands of `spsc` (the compiler)

| Option        | What it does                                   |
|---------------|------------------------------------------------|
| `-o <file>`   | write the bytecode to `<file>`                 |
| `--run`       | run the compiled program                       |
| `--check`     | only compile, do not run                       |
| `--dump`      | print the generated bytecode                   |
| `--stats`     | print the memory statistics                    |
| `--time`      | print the elapsed time                         |
| `--repl`      | the interactive mode                           |

Without `-o` the program is compiled into `out/<name>.spc` and executed.

## The language

### A syntax that is easy for a beginner

* **`;` is optional** — a statement ends with a line break.
* **The `:` in front of a block is optional** — `if x: { }` and `if x { }`.
* **`else if`** works like in C, **`elif`** like in Python (both are fine).
* **The ternary operator** `cond ? a : b`.
* The comparison is `==`, the assignment is `=`; if you mix them up the
  compiler tells you what you meant.

```sps
var name = "Spectra3D"
var version = 3

if version > 2:            // with or without the colon
{
    print("the new version")
}
else if version > 1 {
    print("still playing")
}
else {
    print("the first version")
}

var state = version > 2 ? "new" : "old"
```

### Variables

```sps
let name = "Spectra3D";   // immutable, the type is dynamic
var count = 0;            // mutable
count = count + 1;
count += 5;               // the short form
```

Top level variables are global, the ones inside a function are local.

### Typed declarations (like in C++)

```sps
int suma = 13;         // 64 bit integer
float ratio = 0.5;     // 32 bit float (IEEE 754)
double precise = 0.1;  // 64 bit float
str title = "Spectra3D";
bool ready = true;
list items = [1, 2, 3];
dict table = {"a": 1};

int counter;           // the type is known, the value is the default
```

The types are checked: for the literals at compile time, for the variables at
run time.

```sps
int bad = "text";      // error: cannot initialize 'int' with 'str'
int ok = 13;           // fine
float wide = 13;       // fine: int is converted to float
```

The rules are the ones of C++: `int` is converted to `float`/`double`, the
narrowing is not allowed. The arithmetic promotes the types like in C++:
`float + int` is a `float`, `float + double` is a `double`.

### Blocks and control flow

```sps
if x > 0 {
    print("positive");
} elif x == 0 {
    print("zero");
} else {
    print("negative");
}

while i < 10 {
    i = i + 1;
    if i == 5 { continue; }
    if i == 8 { break; }
}

for item in list {
    print(item);
}
```

### Functions and closures

```sps
def add(a, b) {
    return a + b;
}

def make_counter(start) {
    var count = start;
    def increment() {
        count = count + 1;   // the capture
        return count;
    }
    return increment;
}

var counter = make_counter(10);
print(counter());   // 11
```

A function called `main` is called automatically at the end of the program.

### Anonymous functions, `map`, `filter`, `reduce`

```sps
var double = def(x) { return x * 2 }

print(map(numbers, def(x) { return x * x }))
print(filter(numbers, def(x) { return x > 2 }))
print(reduce(numbers, def(a, b) { return a + b }, 0))
```

### Classes and structures

```sps
class Point {
    float x;
    float y;

    def init(x, y) {
        self.x = x;
        self.y = y;
    }

    def sum() {
        return self.x + self.y;
    }
}

struct Vec2 {
    float x = 0;
    float y = 0;
}

var p = Point(3, 4);
print(p.x, p.sum());
```

* `class` is a reference (the assignment copies the reference),
  `struct` is a value (the assignment copies the object).
* The fields are declared in the body, the methods with `def`, `self` is the
  current object.
* The constructor is the method `init`.

### The inheritance

```sps
class Entity {
    float x = 0;
    var tag = "";

    def init(x) { self.x = x; }
    def describe() { return "Entity(" + str(self.x) + ")"; }
}

class Player extends Entity {
    var health = 100;

    def describe() { return "Player(" + str(self.x) + ")"; }   // the override
}

class Enemy extends Player {
    var damage = 10;
}

var p = Player(3);
print(p.x, p.health, p.describe());     // 3 100 Player(3)
```

The fields and the methods of the parent are inherited, the methods of the
class override the ones of the parent, and the inheritance can be of any
depth.

### switch

```sps
switch state {
    case 1:
    {
        print("one");
    }
    case 2:
    {
        print("two");
    }
    default:
    {
        print("other");
    }
}
```

The cases fall through to the next one, like in C without `break`.

### Error handling

```sps
try {
    print(10 / 0);
} catch err {
    print("caught:", err);
}
```

The error interrupts the `try` block and is passed to `catch` as a string.

### The Result - the errors without the exceptions

```sps
def divide(a, b) {
    if b == 0 {
        return resultError("the division by zero");
    }
    return resultOk(a / b);
}

var r = divide(10, 2);
if isOk(r) {
    print(unwrap(r));            // 5.0
}
else {
    print(r["error"]);           // the message
}

print(unwrapOr(divide(1, 0), 0.0));   // 0.0 - the default for the error
```

| Function         | What it does                                |
|------------------|---------------------------------------------|
| `resultOk(value)` | a successful result                        |
| `resultError(msg)`| a result with an error                     |
| `isOk(result)` / `isError(result)` | the check (bool)             |
| `unwrap(result)` | the value, or a fatal error                |
| `unwrapOr(result, default)` | the value, or the default        |
Without `try` the error stops the program and prints the stack trace.

### Dictionaries

```sps
var user = {"name": "Spectra3D", "age": 3};
user["city"] = "Kyiv";
print(user["name"], len(user));
print(user.has("age"), user.get("none", "default"));
for key in user {
    print(key, "=", user[key]);
}
```

The keys are strings or integers.

### Methods of the types

```sps
print("  Hello  ".strip().upper());   // HELLO
print("a,b,c".split(","));            // [a, b, c]
print("hello".replace("l", "L"));     // heLLo
print("hello".find("ll"));            // 2

var list = [3, 1, 2];
list.append(4);
list.sort();
print(list);                          // [1, 2, 3, 4]
print(list.index(3), list.contains(9));
print(["a", "b"].join("-"));          // a-b

var d = {"a": 1};
print(d.keys(), d.values(), d.items());
```

| Type     | Methods                                                                                 |
|----------|------------------------------------------------------------------------------------------|
| `string` | `upper` `lower` `strip` `split` `replace` `find` `startswith` `endswith` `contains` `count` `isdigit` `isalpha` `isspace` `length` |
| `list`   | `append` `pop` `insert` `remove` `index` `count` `contains` `reverse` `sort` `clear` `join` `length` |
| `dict`   | `get` `has` `remove` `keys` `values` `items` `clear` `length` |

### Formatting: f-strings and `format()`

```sps
var name = "Spectra3D"
var ratio = 3.14159

print(f"Hello, {name}!")
print(f"Ratio: {ratio:.2f}")
print(f"Aligned: {name:>10}|")
print(f"Escaped: {{literal}}")

print(format("Hello, {}!", name))
print(format("{0} and {1}", "first", "second"))
print("{} + {} = {}".format(1, 2, 3))
print("{name} is {age}".format({"name": "SPScript", "age": 1}))
```

* f-strings: the `f` (or `F`) prefix, the expressions inside `{}`.
* The format specs: `{:>10}` (the alignment), `{:.2f}` (the precision),
  `{:5d}`, `{:x}`, `{:<8}`.
* `format()` works both as a function and as a method of a string.
* The named fields `{name}` take their value from a dictionary argument.

### Multi line strings and the line continuation

```sps
var text = """
the first line
the second line
"""

var long = "the first part " + \
           "and the second one"
```

### The membership check

```sps
if 2 in [1, 2, 3] { ... }
if "key" in {"key": 1} { ... }
if "ell" in "hello" { ... }
```

## The SPL format (Spectra3D)

**SPL** is the compact data format of the engine (the **`.spl`** extension).
Compared to JSON: the keys are not quoted, the comments are allowed, the commas
are optional and the strings may use single quotes.

```
{
    // the name of the level
    name = "level_01"
    version = 3
    ratio = 0.5
    enabled = true
    tags = ["engine", "script"]
    player = { hp = 100, name = 'hero' }
}
```

The same data in JSON and in SPL:

```text
JSON: {"player":{"hp":100},"tags":["engine","script"],"name":"level_01","version":3}   78 characters
SPL:  {player={hp=100},tags=["engine","script"],name="level_01",version=3}            68 characters
```

The parser is faster than the JSON one: the keys do not allocate strings.

### Two files — one specification

| File                   | For whom | What it is                                                     |
|------------------------|----------|-----------------------------------------------------------------|
| `include/spl/spl.hpp`  | the engine (C++) | header only: the description of the format + a fast parser and writer. It replaces `json.hpp` |
| `src/spl.c`            | the language (C) | the same for the built-in functions `spl_*`                |

Both implement **one and the same specification** — the test
`tests/spl_compat_test.cpp` parses the same files with both and compares the
result byte by byte:

```text
[ OK ] assets\level_01.spl: 351 characters, name = level_01
[spl] the C library and the C++ header agree
```

### In C++ (the engine)

```cpp
#include "spl/spl.hpp"

spl::Value level;
spl::Error error;
if (spl::load_file("assets/level_01.spl", level, error)) {
    const int hp = level["player"]["hp"].as_int();
    level["player"]["hp"] = hp - 10;
    spl::save_file("assets/level_01.spl", level);
}
```

### In the language

```sps
var data = spl_parse(text)      // the parser
print(spl_stringify(data))      // the compact writer
print(spl_pretty(data))         // the writer with the indentation
spl_save("out/level.spl", data) // write a file
spl_load("out/level.spl")       // read a file
```

The JSON library is complete too: `json_parse`, `json_stringify`, `json_pretty`.

An example of a level: `assets/level_01.spl`.

## The C API for the engine

The language can be embedded into an application (a game engine) through a
**pure C API** — a stable ABI, no dependencies.

```c
#include "sps/sps.h"

SpsContext* context = sps_context_new();
sps_context_set_error_handler(context, on_error, NULL);
sps_register_function(context, "log", native_log, NULL);
sps_context_exec_file(context, "game/main.sps");
```

| Header                          | What it contains                                  |
|---------------------------------|---------------------------------------------------|
| `include/sps/sps.h`            | the main header (it includes the rest)            |
| `include/sps/sps_types.h`      | the types: `SpsValue`, `SpsContext`, the types    |
| `include/sps/sps_value.h`      | the constructors and the conversions of the values |
| `include/sps/sps_context.h`    | the context, the errors, the global variables      |
| `include/sps/sps_function.h`   | the registration of the native functions, the calls |
| `include/sps/sps_class.h`      | the classes of the host: the objects, the methods, the properties |
| `include/sps/sps_compiler.h`   | the compilation, the diagnostics, the bytecode     |

The implementation is in `src/api/` (one file per part): `api_value.c`,
`api_context.c`, `api_function.c`, `api_class.c`, `api_compiler.c`,
`api_version.c`.

### What it gives you

* **The context** — an independent instance of the VM with its own global
  variables (`sps_context_new`, `sps_context_exec`, `sps_context_get_global`).
* **The native functions** — the host registers its functions, the scripts
  call them by name (`sps_register_function`).
* **The classes of the host** — the host gives its own objects (userdata) with
  the methods, the constructor and the **properties**
  (`sps_host_class_new`, `sps_host_class_method`, `sps_host_class_constructor`,
  `sps_host_class_property`).
* **The calls into the script** — the host takes a function of the script and
  calls it (`sps_call`).
* **The errors** — an error handler instead of a fatal exit
  (`sps_context_set_error_handler`).
* **The hot reload** — `sps_compile_file` + `sps_context_run` without
  restarting the host.

The full reference of the engine API — the classes, the functions and the
hooks — is in `docs/engine-api.md`.

```sps

player.position = vec3(0, 1, 0)

var body = Rigidbody(player)
body.gravity = 9.81
body.velocity = vec3(0, 0, 0)
body.applyForce(0, 100, 0)

var zone = Trigger(coin)
```

The classes of the engine: `Entity` `Scene` `Camera` `Light` `Rigidbody`
`Collider` `Trigger` `AudioSource` `Label` `Button` `Vector3` `Color` `Shader`
`Material`.

## Architecture

```
 source.sps
     │
     ▼
 ┌──────────┐   tokens    ┌──────────┐    AST     ┌───────────┐
 │  lexer   │ ─────────► │  parser  │ ─────────► │ compiler  │
 └──────────┘            └──────────┘            └───────────┘
   src/lexer.c             src/parser.c             src/compiler.c
                                                         │ bytecode
                                                         ▼
                                                  ┌───────────┐
                                                  │    VM     │
                                                  └───────────┘
                                                    src/vm.c
```

| File              | What it does                                              |
|-------------------|-----------------------------------------------------------|
| `src/arena.c`     | the arena of the compiler: one free — no leaks            |
| `src/lexer.c`     | the tokenizer of `.sps`                                    |
| `src/parser.c`    | recursive descent → AST                                    |
| `src/compiler.c`  | AST → bytecode, the names, the local slots, the upvalues    |
| `src/vm.c`        | the stack based virtual machine (computed goto)             |
| `src/object.c`    | the strings, the lists, the closures, the classes          |
| `src/dict.c`      | the dictionary (a hash map with open addressing)           |
| `src/methods.c`   | the methods of the types                                   |
| `src/spl.c`       | the SPL format of Spectra3D: the parser and the writer     |
| `src/spslib.c`    | the standard library: the files, the time, the json, the math |
| `src/builtins.c`  | the built-in functions                                     |
| `src/program.c`   | the container of the program + the serialization of `.spc`  |
| `src/api/`        | the implementation of the public C API                     |

### The format of `.spc`

```text
"SPSB" | u32 version | u32 proto_count | the prototypes | the globals | u32 entry
```

## Memory and speed

* **No garbage collector.** There are no pauses — the program never stalls on
  a GC. All the heap objects live on the `vm->objects` list and are released
  **at once** when the virtual machine is stopped. The process does not leak
  memory.
* **The frame arena.** The local slots of all the active frames are taken from
  one buffer (`vm->frame_arena`). The return from a function is a single
  assignment `arena_top = slot_base`, without clearing the slots.
* **The arena of the compiler.** The AST, the names and the prototypes live in
  an arena that is released with a single `arena_release()`.
* **The stack without a cleanup.** The compiler always writes a slot before it
  reads it, so the slots are not initialized when a frame is entered.
* **Computed goto.** The interpreter uses a table of transitions instead of a
  `switch` — that gives about 20% of the speed. The hot fields of the VM (the
  stack, the counter) live in the local variables, and the line number is
  written into the frame only when it changes.

Check the memory statistics:

```bash
bin\spsc.exe examples\stress.sps --stats
```

## The project and the packages

The scripts can be laid out as a project. The file `spsproject.json` describes it:

```json
{
    "name": "MyGame",
    "main": "scripts/main.sps",
    "lib": ["lib"]
}
```

| Field  | What it is                                     |
|--------|------------------------------------------------|
| `name` | the name of the project                        |
| `main` | the main script                                |
| `lib`  | the folders with the packages (the `.sps` libraries) |

The compiler finds the main script and searches the imports in the packages:

```bash
cd examples/project
spsc            # runs scripts/main.sps
```

```
examples/project/
├── spsproject.json
├── lib/
│   └── ui.sps        # a package: import "ui.sps"
└── scripts/
    └── main.sps
```

```sps
// scripts/main.sps
import "ui.sps"

print(button("Play"))
```

### The regular expressions

The engine is written in C11 without any external library: the pattern is
compiled into a bytecode and the matcher walks it with an explicit stack, so
a long text cannot overflow the stack of the process.

| Function | What it does |
|---|---|
| `regex(pattern)` | the compiled pattern (an object of the virtual machine) |
| `regexMatch(re, text)` | the whole text matches the pattern |
| `regexTest(re, text)` | the pattern is found somewhere in the text |
| `regexSearch(re, text)` | the list of the matches: every match is a list with the whole match and the groups |
| `regexReplace(re, text, replacement)` | the text with the replaced matches (`$0`, `$1` .. `$9`, `${1}`) |
| `regexSplit(re, text)` | the list of the parts of the text |
| `regexGroupCount(re)` | the number of the capturing groups of the pattern |

The syntax of the patterns:

| Syntax | What it is |
|---|---|
| `a` `.` | the literal characters and any character except the newline |
| `[abc]` `[a-z]` `[^abc]` | the character classes |
| `\d` `\D` `\w` `\W` `\s` `\S` | the classes of the characters |
| `\n` `\t` `\r` `\xHH` `\\` | the escapes |
| `^` `$` | the beginning and the end of the text |
| `\|` | the alternation |
| `( )` `(?: )` | the capturing groups and the groups without the capture |
| `*` `+` `?` `{n}` `{n,}` `{n,m}` | the quantifiers |
| `*?` `+?` `??` `{n,m}?` | the lazy quantifiers (the shortest match) |
| `\1` .. `\9` | the back references to the capturing groups |

```sps
// the backslash of the pattern is doubled in the string of the script
var mail = regex("(\\w+)@(\\w+)\\.(\\w+)");
print(regexTest(mail, "write to user@spectra3d.org"));
print(regexReplace(mail, "user@spectra3d.org", "$1 at $3"));
print(regexSplit(regex("\\s*,\\s*"), "a, b ,c"));
```

```text
true
user at org
[a, b, c]
```

A broken pattern is a normal error of the script, not a crash:

```sps
try {
    regex("(");
} catch err {
    print(err);   // invalid regular expression: the group is not closed
}
```

## The performance

```bash
spsc examples/bench_complex.sps --time
```

The benchmark does the objects, the method calls, the loops, the strings and the lists at once.

The interpreter uses the computed goto, so the dispatch of the instructions is a single indirect jump. The compiler combines the frequent pairs of the instructions into one (`get a local and a constant`, `get a global and a constant`), and the local slots of a frame are not cleared, because the compiler always writes a slot before it reads it.
